# T-109: Save a deck to the user's Google Drive for teaching

## Phase 1 (built)
In the 🧠 banner, a deck that is not built in shows **Save to Drive for teaching** next to Teach these cards. It makes a `.txt` in
the built-in deck format (`// <Name> (<Commander>)`, `// Bracket N|?`, `// COMMANDER`, `// MAINBOARD`), named
`<Deck name> [B<n or ?>] (<Commander>).txt`. With Web Share Level 2 (`navigator.canShare({files})`, phones and tablets) it opens the share
sheet so the user picks Google Drive and the ManaBox folder; otherwise it downloads the file. Nothing leaves the page by itself. Code:
`saveToDrive`/`driveDeck` in `goldfish/static/app.js`; test `tests/ui/save-to-drive.ui.js`.
Notes: a browser download turns the `?` of an unknown bracket into `_` (the OS forbids it); the shared file keeps `?`. The bracket is
read only from a `// Bracket N` line in the pasted list; otherwise `?`.

## Phase 2 (design only, not built): direct upload from the page
Goal: one tap puts the file in the Drive folder, with no share sheet. ICEYfish is a static site and must never hold a secret. That works:
Google Identity Services (GIS) token flow is a **browser-only OAuth flow that needs only a public client ID** (no client secret).

### How it would work
1. Load `https://accounts.google.com/gsi/client` on first use (not at startup; the service worker's SHELL list stays unchanged, the script
   is fetched online only).
2. `google.accounts.oauth2.initTokenClient({ client_id: CLIENT_ID, scope: 'https://www.googleapis.com/auth/drive.file', callback })`, then
   `requestAccessToken()` from the button's click (a popup, so it must be a user gesture). The token lasts about an hour, is kept in memory
   only, and is never stored.
3. `drive.file` lets the app see and write only files it created or the user opened with it. It cannot list the user's Drive, so it
   **cannot browse to the ManaBox folder by itself**. Two ways to name the folder:
   - **Google Picker** (`https://apis.google.com/js/api.js`, `gapi.load('picker')`, `DocsView(FOLDERS)` + `setSelectFolderEnabled(true)`);
     choosing the folder in the picker grants the app that folder under `drive.file`. Needs a **developer key** (API key, restricted to
     the site and to the Picker API; it is public by design) and the project's number as `appId`. The folder id is remembered in
     localStorage (`isf_drive_folder`, an id, not a secret).
   - Or the user pastes the folder's link once; the id is parsed from it. Uploading into a folder the app did not create or was not given
     fails under `drive.file`, so this only works with the Picker route, so Picker is the one to build.
4. Upload: `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=multipart` with
   `Authorization: Bearer <token>`, metadata `{ name, parents: [folderId], mimeType: 'text/plain' }` and the deck text. CORS is allowed for
   this endpoint. Show "Saved to your ManaBox folder. ICEYfish checks it within the hour."
5. The hourly check (the user's Drive scan) is a separate side that already exists; the file name and format are the same as phase 1.
6. Keep phase 1's share/download as the fallback (no client ID configured, popup blocked, offline).

### What the user must set up (once, in Google Cloud)
1. Go to <https://console.cloud.google.com/> and create a project (for example "ICEYfish").
2. **APIs & Services → Library**: enable **Google Drive API** and **Google Picker API**.
3. **APIs & Services → OAuth consent screen** (Google Auth Platform): user type **External**; app name ICEYfish; support and developer
   email; add the scope `.../auth/drive.file` (a non-sensitive scope, so no Google verification review is needed). Leave the app in
   **Testing** and add the user's own Google account under **Test users** (fine for one person; tokens then expire after 7 days of
   refresh, which does not matter for the token flow). Publishing to **Production** is only needed for other people.
4. **Credentials → Create credentials → OAuth client ID**: type **Web application**. **Authorized JavaScript origins**: the site's origin
   only, `https://<user>.github.io` (no path), plus `http://localhost:8800` for tests if wanted. No redirect URI is needed for the token
   flow. Copy the **Client ID** (`....apps.googleusercontent.com`). It is public; do not copy the client secret anywhere.
5. **Credentials → Create credentials → API key**; restrict it: **Websites** = the same origin, **API restrictions** = Google Picker API
   only. Copy it. It is public by design.
6. Give MAIN three values: the client ID, the API key, and the project number (Project settings). MAIN or a task puts them in a small
   `goldfish/static/drive-config.js` (public constants). None of the three is a secret.
7. The user opens the ICEYfish page once, taps the button, signs in, picks the ManaBox folder, and allows the Drive access prompt
   ("See, edit, create and delete only the specific Google Drive files you use with this app").

### Risks and decisions for MAIN to put to the user
- Testing-mode apps show an "unverified app" warning; fine for the owner alone.
- The popup flow does not work in some in-app browsers (Instagram, etc.); the fallback covers it.
- Adds a Google script load: a privacy point. It loads only after the user taps the button, and the app sends no card data to Google apart
  from the file the user chooses to save.
- Requirement 9 in `PROJECT_STATE.md` ("no outside service, sign-up or key in the code without the user's yes"): this needs the user's yes.
- Test plan if built: mock `google.accounts.oauth2` and `google.picker`, intercept `fetch` to the upload URL, check the multipart body, the
  parent id and the fallback.
